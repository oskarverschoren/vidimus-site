VIDIMUS/FOR AI AGENTS

Let your agent fetch the proof.

“Go to Vidimus and get me the proof for this disputed case.” Vidimus is built to be used by agents too — Claude, ChatGPT or your own automation. Three layers: a readable summary for models (llms.txt), a fully described API (OpenAPI · Swagger) and an MCP server with ready-made tools. Public facts without a key; your own case files with a separate key for your agent, never your organisation's key.

02 · MCP SERVER (CLAUDE CODE, CURSOR, VS CODE, CODEX)

Hosted, nothing to install. Give your agent one address and its own key, never your organisation's key. You create it in the app, under Connect. On the AI assistant tab, your assistant gets a key that looks up and checks, or a key that records in one logbook and then only sees what it recorded itself. Revoking takes effect immediately, without touching your systems. Without a key, only the public tools work.

{"mcpServers": {"vidimus": {
  "type": "http", "url": "https://app.vidimus.be/mcp",
  "headers": {"x-api-key": "${VIDIMUS_MCP_KEY}"}}}}

The key always goes in the x-api-key header (or Authorization: Bearer), preferably from an environment variable, never in a URL.

ProgramDoes it work?
Claude Code, Cursor, VS Code, CodexYes, with the key in the header. The app shows the snippet to copy for each program.
Claude in the browser, the Claude app, ChatGPTNot yet: they ask for a sign-in instead of a key. We are working on it. Until then, they only work for public checks.

Building an integration with your agent. For a system or device (TMS, WMS, sensor), the administrator first creates it under Connect. Your agent then gets a test key (vks_test_…, server name vidimus-test, environment variable VIDIMUS_TEST_KEY): it records nothing, and every response contains "proef": true (“proef” means test). With connection_status, the agent sees what is ready, and it tests with test_measurement or test_registration until the response contains "aanvaard": true (accepted). Then the system's own code sends one message with the test key. Only then does it say “Test passed”, and the administrator creates the live key. That key belongs in the system as VIDIMUS_API_KEY, never in the chat, in code or in an MCP connection.

Note: we have no Vidimus package on PyPI. Anyone who runs pip install vidimus installs someone else's code. Use only the address above.

Tools: verify_registration · passport · list_registrations · list_streams · get_dossier · get_content · register · connection_status · test_measurement · test_registration · create_share · tamper_check · usage · explain.

03 · WITHOUT TRUSTING VIDIMUS

Every evidence bundle contains a stand-alone check script (verify_bundle.py, Python 3 with the cryptography package) and the timestamp files (RFC 3161), including the qualified timestamp from a qualified trust service provider on the EU trusted list. An agent — or your IT team — can therefore check without a single connection to us:

python3 verify_bundle.py bundel.zip     →  GELDIG · 7 van 8 nagerekend (printed in Dutch, a technical status: 7 of 8 recomputed; you compare the Bitcoin block online)
openssl ts -reply -token_in -in tijdstempel.tsr -text   →  time + Merkle root from the timestamping service
https://eidas.ec.europa.eu/efda/tl-browser/             →  the issuer of gekwalificeerd.tsr is listed as qualified on the EU trusted list
